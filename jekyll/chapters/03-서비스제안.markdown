## 1) 서비스 개념

통화/문자 텍스트(또는 오디오)를 입력받아, ①보이스피싱 패턴 탐지 → ②위험도 스코어링 →
③(오디오인 경우) 딥보이스 판별 → ④유사 사기사례 검색 → ⑤판정 근거 생성의 파이프라인을
거쳐 **"위험도 점수 + 왜 그렇게 판단했는지에 대한 근거"**를 함께 반환하는 시스템이다.
판정 결과는 관제 대시보드에서 실시간으로 확인할 수 있고, 고위험으로 판정되면 신고
접수 프로세스로 이어진다.

## 2) 주요 기능 (F-01~F-07)

| ID | 기능 | 설명 |
|---|---|---|
| F-01 | 통화 텍스트 분석 | 기관사칭·공포조성·긴급송금유도·개인정보요구 등 보이스피싱 특징 패턴을 탐지한다 |
| F-02 | 위험도 스코어링 | 0~100점 스코어를 산출하고 저/중/고 3단계 등급으로 분류한다 |
| F-03 | 딥보이스 판별 | 통화 음성이 AI 합성 음성인지 여부를 판별한다 |
| F-04 | 유사사례 매칭 | RAG 기반으로 기존 사기유형 DB에서 유사 사례를 검색한다 |
| F-05 | 판정 근거 제시 | 왜 보이스피싱으로 판단했는지 자연어로 설명한다 (블랙박스 판정 금지) |
| F-06 | 관제 대시보드 | 실시간 탐지 현황과 통계를 시각화한다 |
| F-07 | 신고 연동 | 고위험 판정 시 신고 접수 프로세스를 개시한다 (mock — 6장/부록C 참고) |

## 3) MCP 서버를 통한 도구 분리

통화분석(F-01/F-02) / 사기패턴DB조회(F-04) / 신고연동(F-07) 세 가지 기능을 하나의
모놀리식 서비스에 두지 않고, **MCP(Model Context Protocol) 서버**로 분리해 각각 독립된
도구(tool)로 노출한다(`apps/mcp-server`). 이 저장소 루트의 `.mcp.json`이 이 서버를
Claude Code에 stdio로 직접 등록해두어, Claude Code 안에서 `analyze_call_pattern`,
`lookup_fraud_pattern_db`, `submit_report` 세 도구를 바로 호출·검증할 수 있다. 동시에
같은 애플리케이션 로직을 REST 어댑터(`rest_server.py`)로도 노출해, `apps/api`가 일반
HTTP로 호출하는 운영 경로도 함께 갖춘다 — 즉 "AI 에이전트가 직접 쓰는 도구"와 "웹
서비스가 호출하는 API"를 같은 유스케이스 코드 위에서 이원화한 구조다.

## 4) 설명가능성(N-04) 확보 방안

모든 AI 판정에 근거를 함께 반환한다는 원칙(N-04)을 다음 세 가지로 구현했다.

1. **탐지된 패턴 목록** — 어떤 카테고리(기관사칭/공포조성/긴급송금유도/개인정보요구)의
   어떤 키워드/문구가 매칭됐는지 구조화된 형태로 반환한다.
2. **자연어 설명(F-05)** — 왜 이 위험도로 판단했는지를 요약문+상세 설명으로 제공한다.
3. **유사 사기사례(F-04)** — RAG로 검색한 기존 사기유형 사례를 판정 근거에 결합한다
   (`73ecdb1` 커밋). "이 판정이 과거의 어떤 실제 유형과 비슷한가"를 사람이 직접 비교
   검증할 수 있게 한다.

딥보이스 판별(F-03)도 동일한 원칙을 따른다 — `is_synthetic` 단일 값만 주지 않고,
판별에 쓰인 개별 지표(피치 안정성/스펙트럼 평탄도/묵음 규칙성)가 각각 트리거됐는지를
함께 반환한다(7장 2절 참고).

## 5) 관제 대시보드

프론트엔드(Next.js, `apps/frontend`)는 아래 정보를 실시간으로 보여준다.

- 탐지 현황 목록 (최근 판정된 통화/문자, 위험도별)
- 위험도 분포 및 카테고리별 처리 통계
- 개인정보 마스킹된 통화 내용 (원문은 ADMIN 권한에서만 열람 가능 — N-02×N-03 결합,
  9장/`apps/api/src/main.py`의 `_serialize_call_result` 참고)
