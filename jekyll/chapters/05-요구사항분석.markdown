`docs/RFP.md` 2~3장에서 정의한 요구사항 원문에, 2026-08-31 기준 구현 상태를 덧붙였다.
전 항목이 최소 1차 구현·검증을 마쳤다 — 다만 "1차 구현"과 "실서비스 수준 검증"은
다른 수준이므로, 각 항목의 한계는 명시적으로 함께 적는다(8장 3절 참고).

## 1) 기능 요구사항 (Functional Requirements)

| ID | 요구사항명 | 설명 | 구현 상태 |
|---|---|---|---|
| F-01 | 통화 텍스트 분석 | 공포조성, 기관사칭(검찰/금감원 등), 긴급송금유도 등 패턴 탐지 | 완료 — 규칙 기반(v1) → 로컬 LLM(Ollama, v2)으로 교체 |
| F-02 | 위험도 스코어링 | 0~100점 스코어 산출, 저/중/고 3단계 등급 분류 | 완료 — 합성 데이터셋으로 가중치/임계값 검증(`767eac1`) |
| F-03 | 딥보이스 판별 | 통화 음성이 AI 합성 음성인지 판별 | 완료 — v1(휴리스틱, 임계값 실측 보정 `4b3b0b5`) → v2(검증된 오픈소스 스푸핑 탐지 모델)로 교체, v1은 폴백 겸 N-04 보조 지표로 유지 |
| F-04 | 유사사례 매칭 | RAG 기반으로 기존 사기유형 DB에서 유사 사례 검색 | 완료 — TF-IDF(v1) → 로컬 임베딩(v2) → postgres+pgvector(v3) |
| F-05 | 판정 근거 제시 | 왜 보이스피싱으로 판단했는지 자연어 설명 제공 | 완료 — F-04 유사사례를 판정 근거에 결합(`73ecdb1`) |
| F-06 | 관제 대시보드 | 실시간 탐지 현황과 통계를 시각화 | 완료 — 위험도 분포, 처리 통계, PII 마스킹 반영 |
| F-07 | 신고 연동 | 고위험 판정 시 신고 접수 프로세스 개시 | 완료(mock) — REST/대시보드까지 연결(`27a6178`), 실제 112/경찰청 API는 미연동 |

## 2) 비기능 요구사항 (Non-Functional Requirements)

| ID | 요구사항명 | 설명 | 구현 상태 |
|---|---|---|---|
| N-01 | 감사증적 | 모든 판정 과정을 변경 불가능한(append-only) 로그로 기록 | 완료 — postgres 트리거로 UPDATE/DELETE 자체를 거부 |
| N-02 | 접근통제 | RBAC 기반으로 조회/처리/관리자 권한 분리 | 완료 — apps/api 도입 후 mcp-server REST 어댑터까지 확장(`c9799af`) |
| N-03 | 개인정보 비식별화 | 통화 내용 중 개인정보(이름/계좌번호/전화번호 등) 마스킹 | 완료 — mcp-server 호출 *전* 단계에서 마스킹, N-02와 결합(masked는 누구나/raw는 ADMIN만) |
| N-04 | 설명가능성 | 모든 판정에 추적 가능한 근거 제공 (블랙박스 판정 불가) | 완료 — 탐지 패턴 + 자연어 설명 + 유사사례를 F-05에서 결합 반환 |
| N-05 | 응답시간 | 통화 종료 후 평균 5초 이내에 판정 결과 산출 | 완료(계측) — `vps_analysis_duration_seconds`로 SLA 실측 관측 연결(`1414f30`) |
| N-06 | 확장성 | 신규 사기유형 추가 시 재설계 없이 확장 가능한 구조 | 완료 — 3개 축(판정 알고리즘/검색 알고리즘/감사증적 저장소) 실제 교체로 검증 |

## 3) 제약사항 및 전제조건

- **데이터 제약**: 실제 보이스피싱 통화 녹음은 사용할 수 없다. 공개된 뉴스, 경찰청
  공개자료, 시나리오 기반의 합성 데이터셋을 직접 제작해 사용한다(`docs/RFP.md` 4장,
  `CLAUDE.md`). 딥보이스 판별 데이터셋도 공개 TTS 합성 음성과 공개 인간 발화
  코퍼스(LibriSpeech)로 구성했다(`4b3b0b5`).
- **로컬 우선 개발 환경**: F-01/F-02 v2는 로컬 Ollama(EXAONE 3.5 2.4B)를, F-04는
  로컬 sentence-transformers 임베딩 모델(jhgan/ko-sroberta-multitask)을, 모바일 STT는
  faster-whisper를 쓴다 — 전부 외부 API 키 없이 로컬 GPU(RTX 3050)에서 동작하도록
  구성했고, GPU가 없거나 모델이 안 떠 있으면 각각 규칙 기반/CPU/에러 응답으로 우아하게
  폴백한다.
- **1인 개발 전제**: 조직 구성/역할 분담(7장 3절)이 팀 프로젝트와 다르다 — 기획부터
  구현·인프라·문서화까지 단일 개발자가 순차적으로 수행한다는 전제가 개발 일정(7장
  4절)과 위험요소 관리(8장 3절)에 그대로 반영된다.
- **인프라 재사용 전제**: Docker Compose 구성, Prometheus/Grafana 스택, 헥사고날
  아키텍처, EC2 배포, Nginx/Cloudflare 연동 등은 이전 개인 프로젝트
  [gpu-fleet-ops](https://github.com/pmhllll12/gpu-fleet-ops)에서 검증한 패턴을
  그대로 재사용한다는 것을 전제로 설계했다(README "재사용한 인프라 스킬" 참고).
