## 1) 목표 사용자

실제 사업화를 전제하지 않는 포트폴리오 프로젝트이지만, 가상 발주처(금융사기대응센터)
설정에 맞춰 목표 사용자를 다음과 같이 정의했다.

- **금융기관 콜센터/상담원** — 통화 중 실시간으로 위험도 경고와 판정 근거를 받아 상담
  스크립트를 조정할 수 있는 관제 화면 사용자
- **통신사/보안 서비스 제공자** — 문자/통화 필터링 파이프라인에 탐지 엔진을 API로
  붙이는 B2B 연동 주체
- **개인 이용자** — 의심스러운 통화를 캡처해 딥보이스 여부와 위험도를 직접 확인하려는
  최종 사용자

## 2) 시장 현황과 이 프로젝트의 성격

보이스피싱 탐지/차단 시장에는 이미 통신사 스팸 필터, 금융권 이상거래탐지시스템(FDS),
정부기관의 보이스피싱 통합신고 플랫폼(더치트, 시티즌코난 등) 같은 기존 서비스가
존재한다. 이 프로젝트는 그 시장에 새 제품을 내놓으려는 것이 아니라, **그런 시스템이
공통으로 요구하는 두 축 — "설명가능한 AI 판정"과 "관측 가능한 인프라 운영" — 을
개인이 엔드투엔드로 구현할 수 있음을 증명**하는 데 목적이 있다(1장 참고). 그래서
경쟁사 비교나 시장 규모 추정 같은 항목은 이 문서의 핵심이 아니며, 사업 타당성보다
기술적 완성도(F-01~F-07 구현, N-01~N-06 반영, 헥사고날 아키텍처, 관측성)를 자기
검증하는 체크리스트로 `docs/RFP.md` 6장을 대신 두었다.

## 3) 수익 모델에 대한 입장

이 프로젝트는 수익화를 설계하지 않는다. 다만 만약 B2B SaaS 형태로 확장한다면 아래
방향이 자연스럽다는 점만 남겨둔다.

- 통화량 기반 API 사용료 (분석 건수 과금)
- 관제 대시보드 시트 수 기반 구독료 (콜센터/상담팀 단위)
- 딥보이스 판별 정확도가 검증된 v2 모델로 교체된 뒤에는, 판별 API 단독 상품화 가능성

## 4) 차별화 전략

- **"블랙박스 판정 불가"** — 위험도 점수만 주는 경쟁 제품과 달리, 매 판정에 탐지
  패턴/자연어 설명/유사사례 근거를 항상 함께 반환한다(N-04, 3장 4절).
- **재설계 없는 확장성(N-06)** — 신규 사기유형이 등장했을 때 카테고리 enum과 규칙
  dict만 추가하면 되고, `application/` 계층 코드는 건드리지 않는다. 이는 이론이 아니라
  이 프로젝트에서 판정 알고리즘(규칙→로컬 LLM)과 검색 알고리즘(TF-IDF→임베딩→pgvector)을
  실제로 3번 교체하면서 매번 application 계층 diff가 0줄이었다는 실측 근거가 있다
  (`docs/design.md`, 6장 2절).
- **관측 가능한 AI 인프라** — Prometheus로 판정 소요시간(N-05 SLA), 딥보이스 판별
  결과 분포, LLM/임베딩 모델의 GPU 메모리 점유까지 노출해, "AI 파이프라인이 실제로
  얼마나 빠르고 안정적으로 도는가"를 판정 정확도와 별개로 관측할 수 있게 했다.
